# 沪深300 五均线四级发散策略 · xtdata 本地回测

把原来的 QMT 内置 Python 脚本（`ContextInfo` + `passorder`）改写成
**xtdata 取数 + 自带撮合引擎**的本地回测，选股逻辑和参数保持一致。

## 选股逻辑

```
四级发散：
    s1 = (MA5  - MA10) / MA10
    s2 = (MA10 - MA20) / MA20
    s3 = (MA20 - MA30) / MA30
    s4 = (MA30 - MA60) / MA60
    总发散 = s1 + s2 + s3 + s4

入选条件（两条都要满足）：
    1. MA5 > MA10 > MA20 > MA30 > MA60      多头排列
    2. s1~s4 全部大于前一交易日              发散同步扩大

排序取前 5 只等权持有，次日开盘调仓。
```

> ⚠️ **排序方向**：原脚本里 `results.sort(key=..., #reverse=True)` 的 `reverse`
> 被注释掉了，所以实际取的是**总发散度最小**的 5 只，和上面那行注释写的
> "从大到小"相反。这里默认保持原脚本的真实行为（`SORT_ASCENDING = True`），
> 想改成取发散度最大的，加 `--descending` 或把配置改成 `False`。
> 两种跑一遍对比一下，很可能是当初写错了。

## 前置条件

xtdata 的数据由本机 QMT / MiniQMT 客户端提供，所以需要：

1. 装好 QMT / MiniQMT 并**保持登录**；
2. `from xtquant import xtdata` 能 import（客户端自带的 `xtquant` 目录加进
   Python 环境，或直接用客户端自带的 Python）。

## 快速开始

```bash
# 首次：补下载行情（指数 + 区间内出现过的全部成分股）
python -m hs300_ma_divergence --start 20230101 --end 20241231 --download

# 之后直接回测，读本地数据
python -m hs300_ma_divergence --start 20230101 --end 20241231

# 只抓历史成分股写缓存
python -m hs300_ma_divergence --start 20200101 --end 20241231 --dump-constituents
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--cash` | 初始资金，默认 100 万 |
| `--max-holdings` | 最大持仓数，默认 5 |
| `--descending` | 按总发散度从大到小取前 N（原脚本实际是从小到大） |
| `--granularity day\|month` | 成分股快照粒度，默认 month |
| `--dividend front\|none\|back\|...` | 复权方式，默认前复权 |
| `--slippage 0.001` | 滑点比例 |
| `--no-limits` | 不考虑一字涨跌停的成交限制 |
| `--quiet` / `--all-candidates` | 控制日志详细程度 |

## 历史成分股（point-in-time）

**这是本地回测最容易出错的地方。** 用今天的沪深300成分股去跑三年前的历史，
当年被调出的票（往往走弱）不在池子里、当年还没调入的票（往往走强）却提前出现，
回测收益会系统性偏高，这叫幸存者偏差。

取数优先级：

1. **本地缓存 CSV**（`data/hs300_constituents.csv`）——最可靠，也便于离线复现；
2. `xtdata.get_stock_list_in_sector('沪深300', real_timetag)` ——
   新版 xtquant 支持传毫秒时间戳取历史成分，旧版没有这个参数会自动跳过；
3. 退回"当前成分股" —— **默认禁止**，要显式加 `--allow-current-constituents`，
   日志里会打印醒目警告。

三条都拿不到时直接报错，而不是偷偷用当前成分股糊弄过去。

程序还会自检：如果不同日期查回来的名单完全相同，说明接口其实忽略了时间参数，
一样按"取不到历史成分"处理。

### 自己准备成分股数据

如果你的 xtquant 版本不支持历史成分，可以从任何渠道（券商终端、Wind、
tushare、公开的指数样本调整公告）导出一份 CSV，格式很简单：

```csv
date,stock
20230103,600000.SH
20230103,600009.SH
...
20230703,600000.SH
```

每个"快照日"把当时的全部成分股各写一行，放到 `--cache` 指定的路径即可。
不需要每个交易日都有，程序会用不晚于当日的最近一个快照前向填充
（沪深300 每年 6/12 月各调整一次，半年一个快照就够）。

## 撮合假设

| 项 | 处理方式 |
| --- | --- |
| 信号与成交 | T 日收盘算信号，**T+1 开盘**成交（对应原脚本 `quickTrade=0`） |
| T+1 | 当日买入的票当日不可卖，顺延到下一交易日 |
| 停牌 | 当日没有 K 线 → 既买不进也卖不掉，下一个交易日重试 |
| 涨跌停 | 一字涨停买不进、一字跌停卖不掉（`--no-limits` 可关） |
| 手续费 | 佣金万 2.5 双边、单笔最低 5 元；卖出印花税千 1；过户费万 0.1 双边 |
| 仓位 | `min(总资产 × 20%, 可用资金 ÷ 待买只数) × 0.98`，向下取整到手（与原脚本一致） |
| 估值 | 每日收盘价 mark-to-market，停牌按最近成交价 |

未成交的原因（停牌 / 一字板 / 资金不足 / T+1 未解禁）会计数，回测结束打印。

## 输出

每次回测在 `backtests/` 下生成一个带时间戳的目录——**跑多少次留多少份，
不会互相覆盖**，正好用来做参数对比：

```
backtests/20240918_103000_hs300_ma/
    summary.txt       指标汇总 + 本次全部参数
    summary.json      同上，机器可读
    equity.csv        每日权益曲线（现金 / 持仓市值 / 总资产 / 持仓数）
    trades.csv        每笔成交（信号日、成交日、价格、数量、费用、成交后现金）
    round_trips.csv   配对后的每笔平仓盈亏
    signals.csv       每日候选数量与目标组合
```

指标：总收益、年化、最大回撤及其区间、年化波动、夏普、成交笔数、胜率、
单笔平均收益、总手续费。

## 已知局限

1. **复权**：默认前复权，均线不会被除权跳空污染，但涨跌停价是用复权价算的，
   与真实的涨跌停价有细微出入（比例仍是 10%/20%，影响很小）；
2. **分红**：前复权已隐含分红再投资的近似，没有单独建模现金分红；
3. **成分股粒度**：默认按月取快照，指数调整生效日当天到月初之间会有几天偏差，
   要精确就用 `--granularity day`（慢很多）；
4. **ST / 退市**：没有单独过滤，历史成分股名单里本身就不太会出现；
5. **成交量**：不检查自己的委托量相对当日成交量的占比，大资金要自己留意冲击成本。

## 代码结构

```
hs300_ma_divergence/
├── config.py         全部参数
├── signals.py        均线、四级发散、入选条件、排序（纯函数）
├── constituents.py   历史成分股：缓存 / xtdata / 兜底，前向填充
├── data.py           xtdata 封装 + 按日期索引的 Bars 容器
├── engine.py         撮合引擎：T+1、费用、涨跌停、停牌、仓位
├── metrics.py        绩效指标与配对平仓
├── report.py         结果落盘
└── run.py            命令行入口
```

`signals.py` / `engine.py` / `metrics.py` 都是纯函数，不依赖 xtquant，
`tests/fake_xtdata.py` 模拟了 xtdata 接口，`python -m pytest` 可以在没有
QMT 的机器上跑完整流程。
