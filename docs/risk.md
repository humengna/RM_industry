# 风控模块：为什么会买到跌停票，以及怎么过滤

## 1. 根因：打分公式天生偏爱"要崩的票"

动量分数 = `(exp(slope × 244) - 1) × |R²|`，而 `LOOKBACK_DAYS = 5`。

这意味着：

- **5 天窗口 + 244 天年化**把短期斜率放大到极端。连续 2 个涨停（+21%）的票，
  年化收益率是天文数字，其他票根本排不上号；
- **R² 奖励"走得直"**。一路一字板的票 R² ≈ 1，分数被再乘满分；震荡上涨的票
  R² 低，反而被压下去。结果就是：**排名第一几乎恒等于全市场当下最疯的那只**；
- **股票池是整个沪深 A 股**（`CONCEPT_SECTORS = ['沪深a股']`），
  样本越大，"最疯的那只"就越极端；
- **满仓单票**，买错一次就是全账户 -10%（创业板/科创板 -20%）；
- **买点是次日开盘**。连板票次日开盘往往已经高开，情绪一旦退潮，
  当天就是"高开 → 炸板 → 跌停"，第二天甚至一字跌停，想跑都跑不掉。

所以这不是"偶尔选到烂票"，而是**选股函数的系统性偏好**。风控要做的，
就是在这个偏好和下单之间加一道闸。

> 顺带一提：把 `LOOKBACK_DAYS` 从 5 调到 20~29（原脚本注释里的备选值），
> 能从源头削弱这种偏好，代价是换手降低、反应变慢。建议和风控一起做 A/B 回测。

## 2. 三道防线

```
板块成分股
   │  ① 股票池过滤（universe.py）  停牌 / ST / 市值 / 跌停
   ▼
动量打分排名
   │  ② 日线风控（risk.py）  过热 / 波动 / 流动性 / 结构 / 开盘跳空
   │  ③ 分钟线风控（intraday.py）  炸板 / 尾盘跳水 / 收在低位 / 跌破VWAP /
   │                               高位派发 / 触及跌停 / 天量滞涨
   │     第 1 名被否决 → 顺延看第 2 名，最多试 RISK_MAX_CANDIDATES 只
   ▼
目标股 → 择时 → 下单
   │  ④ 持仓风控（signals.py）  硬止损 -15% + 移动止损 -10%
   ▼
持仓
```

日线风控先跑，通过了才去拉分钟线（分钟数据量大，能省则省）。

关键设计：**否决不等于当天空仓**。`select_target` 沿排名往下走，
取第一只通过体检的票；只有前 N 名全军覆没才空仓。

## 2.5 为什么不能"命中一条就否决"

二十多条规则如果全用硬否决，每条哪怕有 90% 的通过率，连乘下来也只剩 12%——
再叠加"只看前 5 名"，结果就是**天天没票可买**。所以判定分两层：

| 层 | 规则 | 行为 |
| --- | --- | --- |
| 硬否决 `RISK_HARD_RULES` | 连板、炸板、近日盘中触及跌停、动量分数 ≤ 0、成交额过小、次新股、数据不足 | 命中即出局，不看扣分 |
| 扣分 `RISK_RULE_PENALTY` | 其余全部规则 | 每条扣 1~4 分，累计 **≥ `RISK_PENALTY_LIMIT`(=4)** 才出局 |

扣分权重（未列出的默认 1 分）：

| 规则 | 扣分 | 含义 |
| --- | --- | --- |
| `gap_up` / `gap_down` / `tail_selloff` | 4 | 单条即可否决——当日跳空和前一日尾盘跳水是高精度信号 |
| `intraday_crash` / `tail_dump` / `high_distribution` / `limit_down_history` | 2 | 两条凑齐就出局 |
| 其余（涨幅、乖离、波动、量比、换手、收在低位、跌破 VWAP…） | 1 | 单条不致命，三条以内都还能买 |

所以"这只票涨得多 + 偏离均线 + 放了点量"（1+1+1=3 分）仍然可以买，
但再加一条就出局了。**嫌严就把 `RISK_PENALTY_LIMIT` 调大**，
`=1` 就退回"命中任何一条就否决"的老口径。

### 三档预设

`config.py` 末尾的 `RISK_PRESET` 一行切换整套阈值：

```python
RISK_PRESET = 'normal'   # 'loose' | 'normal' | 'strict'
```

| 档位 | 扣分上限 | 候选扫描 | 适用 |
| --- | --- | --- | --- |
| `loose` | 8 | 50 只 | 只留硬否决类规则，软规则基本不拦；嫌交易太少时用 |
| `normal` | 4 | 30 只 | 默认 |
| `strict` | 1 | 10 只 | 命中任何一条即否决，阈值也全部收紧；调参时用来对照 |

三档里连板都是硬否决，不会因为放松档位就去买连板票。

### 候选扫描深度

`RISK_MAX_CANDIDATES` 是另一个关键量。打分公式天然把连板票排在最前面，
**只看前 5 名基本全是过热票**，风控再合理也是天天空仓。默认 30 只
（约等于"在排名前 0.6% 里挑一只能买的"），`loose` 档 50 只。

### 全被否决时怎么办

日志会打印原因分布：

```
[风控] 30 只候选全部否决，原因分布: [('gain_short', 24), ('bias', 19), ('failed_limit_up', 6), ...]
```

看这一行就知道是哪条规则拦死了全场，针对性地调它，而不是整体放松。

还有两个应急开关：

- `RISK_FALLBACK_TO_BEST = True`：全被否决时买"扣分最低且无硬否决"的那只
  （硬否决的票永远不会被兜底买入）。默认 `False`——宁可空仓；
- `RISK_DEBUG = True`：打印每只候选的全部指标数值，用真实数据校准阈值。
  日志会很长，建议只在短区间回测时打开。

## 3. 每条规则拦什么

| 规则 | 参数 | 默认 | 拦截的情形 |
| --- | --- | --- | --- |
| 连板数 | `RISK_MAX_CONSECUTIVE_LIMIT_UP` | 0 | **硬否决**。最关键的一条：前一日涨停就不碰，涨停次日开盘买入是跌停风险最大的场景 |
| 近期涨停次数 | `RISK_MAX_LIMIT_UP_COUNT` / `RISK_LIMIT_UP_WINDOW` | 3 / 10 日 | 扣 1 分。10 天内 4 次以上涨停 = 正在被爆炒 |
| 短期涨幅 | `RISK_MAX_GAIN_SHORT` / 窗口 | 40% / 5 日 | 扣 1 分。本策略选的就是最强动量，这条卡太死会和选股逻辑直接打架 |
| 中期涨幅 | `RISK_MAX_GAIN_LONG` / 窗口 | 100% / 20 日 | 扣 1 分 |
| 乖离率 | `RISK_MAX_BIAS` / `RISK_BIAS_WINDOW` | 30% / MA20 | 扣 1 分。股价拉离均线太远，均值回归势能越大 |
| 近期跌停 | `RISK_MAX_LIMIT_DOWN_COUNT` / 窗口 | 1 / 60 日 | 扣 2 分。吃过跌停的票容易再吃第二次 |
| 平均振幅 | `RISK_MAX_AMPLITUDE` / 窗口 | 12% / 5 日 | 扣 1 分。日内上蹿下跳，止损经常来不及 |
| 年化波动率 | `RISK_MAX_VOLATILITY` / 窗口 | 120% / 20 日 | 扣 1 分 |
| 量比 | `RISK_MAX_VOLUME_RATIO` / 窗口 | 5.0 / 5 日 | 扣 1 分。天量往往是出货日 |
| 换手率 | `RISK_MAX_TURNOVER` | 40% | 扣 1 分。需要流通股本，取不到则跳过 |
| 成交额 | `RISK_MIN_AMOUNT` / 窗口 | 5000 万 / 5 日 | **硬否决**。流动性太差，跌停时挂单根本卖不掉 |
| 次新股 | `RISK_MIN_LISTED_DAYS` | 90 天 | **硬否决**。次新股波动与炒作程度都远高于均值 |
| 高开 | `RISK_MAX_GAP_UP` | 7% | 扣 4 分（单条即否决）。开盘就冲高，买在最贵的位置 |
| 低开 | `RISK_MAX_GAP_DOWN` | 7% | 扣 4 分。开盘大幅低开多半是利空，当天奔跌停去的 |
| 动量分数 | `RISK_MIN_SCORE` | 0.0 | **硬否决**。分数 ≤ 0 说明没有上涨趋势，不"矮子里拔将军" |

把任一参数设为 `None` 即关闭该项检查。

## 3.5 分钟线风控：日线看不见的那一半

日线只告诉你"涨了多少"，看不到"怎么涨的"。同样是收盘 +6%，
一整天稳步上台阶、和摸到涨停后炸板砸下来，次日的命运完全不同——
后者才是跌停的常客。这层检查只用**当前交易日之前**的完整交易日分钟线
（当日分钟线在 09:31 决策时还不存在）。

| 规则 | 参数 | 默认 | 说明 |
| --- | --- | --- | --- |
| 炸板 | `INTRADAY_MAX_FAILED_LIMIT_UP` | 0 | **硬否决**，最强的单项信号：盘中摸到涨停却没封住，说明接盘资金已经在跑，次日补跌概率最高。日线完全看不出来（收盘价不是涨停价） |
| 盘中触及跌停 | `INTRADAY_MAX_LIMIT_DOWN_TOUCH` | 0 | **硬否决**。摸过跌停的票有惯性，次日往往继续。日线只有收盘跌停才看得到 |
| 尾盘跳水 | `INTRADAY_MIN_TAIL_RETURN` | -4% | 扣 4 分（单条即否决）。 最后 30 分钟（`INTRADAY_TAIL_MINUTES`）的跌幅。尾盘砸盘 → 次日低开 → 低开就容易奔跌停 |
| 收在日内低位 | `INTRADAY_MIN_CLOSE_POSITION` | 0.15 | 扣 1 分。 收盘价在当日 `(close-low)/(high-low)` 的位置。贴着最低价收盘说明抛压没释放完 |
| 跌破 VWAP | `INTRADAY_MIN_VWAP_GAP` | -2.5% | 扣 1 分。 收盘价低于当日成交额加权均价，意味着当天买入的人平均浮亏，次日一有风吹草动就集体离场 |
| 日内最大回撤 | `INTRADAY_MAX_DRAWDOWN` | -10% | 扣 2 分。 盘中从高点到之后低点的最大跌幅，衡量日内脆弱程度 |

**成交金额维度**（这是分钟线相对日线最大的信息增量——日线只有一个总额，
分钟线能看出这些钱是在什么价位、什么时段、往哪个方向打出来的）：

| 规则 | 参数 | 默认 | 说明 |
| --- | --- | --- | --- |
| 抛压占比 | `INTRADAY_MAX_DOWN_AMOUNT_RATIO` | 0.70 | 扣 1 分。 下跌分钟的成交额 / 全天成交额。超过 60% 说明当天的钱主要是在往下砸的过程中打出来的 |
| 尾盘出货 | `INTRADAY_MAX_TAIL_AMOUNT_RATIO` | 0.45 | 扣 2 分。 尾盘成交额占比过高**且**尾盘收跌才否决——单纯尾盘放量拉升不算坏事 |
| 高位派发 | `INTRADAY_MAX_POST_HIGH_AMOUNT_RATIO` | 0.75 | 扣 2 分。 日内最高点**之后**的成交额占比。冲高之后大部分成交金额是在回落中完成的，就是主力在高位出货 |
| 天量滞涨 | `INTRADAY_MAX_AMOUNT_SPIKE` | 5.0 | 扣 1 分。 最近一日成交额 / 前几日均额。放量 3 倍以上却没封住涨停 = 见顶放量（封死涨停的放量豁免，交给日线的连板规则拦） |

判定口径：**炸板和触及跌停统计最近 `INTRADAY_DAYS`(=3) 天**（这两件事有记忆效应），
其余日内结构与成交额指标**只看最近一个完整交易日**（对次日最有预测力，
越往前的日内细节噪声越大）。

### 关于分钟数据

QMT 默认不一定下载了 1 分钟历史数据。取不到分钟线时：

- `INTRADAY_REQUIRE_DATA = False`（默认）：跳过这层检查并打印一次提示，
  策略照常运行；
- `INTRADAY_REQUIRE_DATA = True`：直接否决。**设 True 之前先确认本地有数据**，
  否则策略会整段空仓。

在 QMT 客户端用「数据管理 → 补充数据」下载标的的 1 分钟历史数据即可。
取数按需进行：日线风控就没通过的候选不会去拉分钟线，一般每根 bar 只拉 1~2 只。

### 大盘风控

`MARKET_FILTER_ENABLED`：沪深 300 收盘价跌破 MA20 视为大盘走弱。
个股跌停在大盘破位时是成群出现的，这一条能过滤掉相当一部分系统性风险。

- `MARKET_FILTER_ACTION = 'no_new'`（默认）：不开新仓，已有持仓交给择时和止损；
- `MARKET_FILTER_ACTION = 'exit_all'`：直接清仓离场，更保守。

### 持仓风控

- **硬止损** `STOP_LOSS_RATIO = -0.15`：相对成本价，原有逻辑保留；
- **移动止损** `TRAILING_STOP_RATIO = 0.10`：相对持仓期间最高价回撤 10% 离场。
  动量票的典型死法是"先赚 30%，再一路还回去还倒亏"，固定止损要等到 -15% 才动，
  移动止损能在冲高回落的早期就走；
- **一字跌停卖不掉** `ASSUME_LIMIT_DOWN_UNSELLABLE = True`：当日最高价即跌停价时，
  卖单其实排不上队。回测里跳过这笔卖出、顺延到下一交易日，
  避免回测结果比实盘好看（这点很重要，否则回测会系统性低估跌停的损失）。

另外，持仓风控现在**每根 K 线都执行**，不再因为"今天没选出标的"就跳过——
原逻辑里股票池为空或候选被过滤时会直接 `return`，持仓当天就没人管了。

## 4. 怎么验证效果

1. **看否决统计**：回测结束时 `stop()` 会打印
   `[风控汇总] 候选股被否决次数: [('limit_up_streak', 128), ('failed_limit_up', 61), ...]`，
   能直接看出哪条规则在起作用、是不是拦得太狠；
2. **A/B 回测**：把 `RISK_ENABLED` 在 `True` / `False` 之间切换跑两遍，
   对比最大回撤、单笔最大亏损、跌停买入次数；
3. **单条消融**：怀疑某条规则拦过头，就把它设成 `None` 单独跑一遍。

调参方向（按优先级）：

1. **嫌交易机会太少**：先看原因分布，是哪条在拦。通用做法依次是
   `RISK_PENALTY_LIMIT` 4 → 6、`RISK_MAX_CANDIDATES` 30 → 50，
   或直接 `RISK_PRESET = 'loose'`；
2. **某一条明显拦过头**：把那一条的阈值单独放宽，或在 `RISK_RULE_PENALTY`
   里把它的扣分降到 1，实在没用就设成 `None` 关掉；
3. **还想更稳**：`RISK_PENALTY_LIMIT` 调到 2~3，`MARKET_FILTER_ACTION`
   改成 `'exit_all'`。连板、炸板这些硬否决不建议动。

## 5. 还没做、但值得做的

按预期收益排序：

1. **分散持仓**：目前是单票满仓，风控做得再好，单票跌停也是账户 -10%。
   改成动量前 3~5 名等权，能把单只票的杀伤力直接除以 N——这是降低跌停伤害
   最有效的一步，但会改变策略结构（需要改调仓逻辑和资金分配）；
2. **拉长动量窗口**：`LOOKBACK_DAYS` 20~29，从源头降低对连板票的偏好；
3. **分数上限**：分数高到离谱（例如年化 100 倍以上）本身就是异常信号，
   可以直接截断，而不是靠涨幅/连板间接拦；
4. **盘中二次确认**：实盘版可以在 09:31 用 `get_full_tick` 看竞价量能和分时，
   开盘就走弱则放弃买入（回测数据粒度不够，做不了）；
5. **行业/概念集中度**：同一概念内轮动时，避免连着几天买同一题材的不同票。

需要哪一条可以继续加，第 1 条改动最大、收益也最大。
